1. Executive Summary und Zielbild
Ziel ist eine KI-Infrastruktur die vier Anforderungen gleichzeitig erfüllt:
Statt eines monolithischen Riesenmodells wird ein Cluster aus physisch getrennten,
domänenspezialisierten Basis-Modellen über einen deterministischen Datenbus
orchestriert.
Kernprinzip: Wissenstransfer findet nicht durch vermischte Gewichte statt, sondern
durch getypten Datenaustausch auf einem zentralen Board. Training, Zertifizierung und
Hardware-Zuweisung sind lokal pro Knoten. Das Blackbox Problem wird physisch
zerschlagen.
Für Meta Muse bedeutet das: Nicht ein großes Llama das alles kann, sondern ein
Orchestrator der viele kleine, hochoptimierte Llamas steuert.
2. Design Prinzipien
Selbst optimierbar: Jedes Modul lernt aus eigenen Fehlern ohne globales
Retraining
Leichter trainierbar: Lokales LoRA Training, keine globale Re-Zertifizierung
Genauer und schneller: Nur relevante Experten aktiv, parallel statt seriell, kalibrierte
Confidence
Auditierbar: Jeder Entscheidungspfad geloggt mit Provenance
1. Harte physische Isolation: Jedes Fach-Modell hat eigene Gewichte, eigenen
Loss, eigene Hardware. Kein Shared Parameterraum.
2. Determinismus vor Wahrscheinlichkeit: Bei gleichem Input, gleichem Model
Hash und gleichem Seed muss gleicher Output entstehen.
3. TMR für kritische Pfade: Routing ist dreifach redundant mit 2-aus-3 Voting und
architektonischer Diversität.
4. Getypter Datenaustausch statt Gewichtsvermischung: Cross-Domain Transfer
über Blackboard Pattern, nicht über gemeinsames Netz.
5. LRU Prinzip: Jede Einheit ist Line Replaceable. Austauschbar, rollback fähig, ohne
Gesamtsystem Stopp.
6. Audit by Design: Jede Entscheidung hat Trace ID, Provenance und signierten
Model Hash.

4. Modul 1: TMR Router Cluster
4.1 Warum TMR
Ein einzelner Router ist Single Point of Failure. Fällt er, fällt alles. In der Avionik sind
kritische Steuerungen dreifach redundant. Gleiches hier.
4.2 Router Spezifikation
Drei quantisierte Router mit Diversität in Architektur und Trainingsdaten:
Alle Router: quantisiert INT8, Latenz Ziel < 50ms p95, Edge TPU fähig.
Output Format Router:
Router A: Transformer 250M, trainiert auf Intent Klassifikation, Daten Slice A
Router B: Mamba State-Space 180M, trainiert auf Task Graphen, Daten Slice B
Router C: Distilled 120M, trainiert nur auf Failure Fällen von A und B, Daten Slice C

4.4 Model Registry Router
Jeder Router versioniert, signiert, mit Training Data Hash. Rollback in < 30s. Registry

function tmr_vote(R_a, R_b, R_c):
if hash(R_a.dag_proposal) == hash(R_b.dag_proposal):
return majority(R_a, R_b, confidence_weighted)
if hash(R_a.dag_proposal) == hash(R_c.dag_proposal):
return majority(R_a, R_c)
if hash(R_b.dag_proposal) == hash(R_c.dag_proposal):
return majority(R_b, R_c)
// total disagreement - kritischer Fall
validated = max_by_confidence(R_a, R_b, R_c)
validated.flag = "TMR_DISAGREEMENT"
validated.flag2 = "REVIEW_REQUIRED"
log_audit(
event="tmr_disagreement",
dag_id=current_dag_id,
proposals=[R_a,R_b,R_c],
confidence_spread=max(c)-min(c)
)
trigger_dataset_write("router_failures.jsonl", [R_a,R_b,R_c])
return validated

routing_precision > 95% gemessen gegen Golden Set

6. Modul 3: Semantischer Bus - Shared Context Board
6.1 Problem und Lösung
Harte Isolation verhindert Catastrophic Forgetting, blockiert aber zufälligen CrossDomain Transfer. Lösung: Transfer auf Kommunikations-Ebene wie CAN-Bus im Auto.
Vor tiefer Inferenz extrahiert jedes Modul abstrakte Muster und publisht sie.

7. Modul 4: Domänen Experten
7.1 Isolation
Jedes Experten-Modell: eigene Gewichte, eigene Loss Funktion, eigene Evaluierung,
eigene Hardware. Kein Shared Encoder.
publish(pattern: Pattern) -> bool, validiert gegen Schema Registry, ACL
Check

ack(pattern_id, module_id) -> bool
get_patterns(dag_id) -> list<Pattern>

Schreiben nur im eigenen Namespace
Lesen global aber nur getypte Felder
Kein direkter Modul zu Modul Call
TTL und Versionierung, automatische GC nach TTL
Jeder Publish geloggt mit dag_id
Physik/Mathe Experte: Loss = numerische Stabilität + Einheitenkorrektheit +
Formel Konsistenz. Trainiert auf Lehrbüchern, Papers, Simulationen.
Code/Logik Experte: Loss = Syntax Validität + Unit Test Pass Rate + Typ
Korrektheit. Trainiert auf Code + Tests.
Sprache/Struktur Experte: Loss = semantische Kohärenz + Format Treue
Markdown/JSON.
Ethik/Logik Experte: Loss = Regelkonformität + Konsistenz.

7.2 Experten Output Format

Kalibrierung ist Delta Prüfung wertlos.

8. Modul 5: Deterministische Fusions-Schicht
8.1 Aufgabe
Fusion darf nicht konkatinieren. Sie muss Widersprüche auflösen wie Endmontage in
Automobil Fabrik. Physikalische und logische Kompatibilität erzwingen.
8.2 Konflikt Taxonomie
TYPE_MISMATCH: int vs float64
UNIT_MISMATCH: W vs kW, Celsius vs Kelvin
CONFIDENCE_GAP: |c_physik - c_code| > 0.25
LOGIC_CONTRADICTION: Formel sagt A, Code implementiert B
FORMAT_VIOLATION: Output nicht gegen Schema valide

8.3 Fusions Algorithmus vollständig
function fuse(expert_outputs: list<E_i>, dag_id):
delta_conf = max(c_i) - min(c_i)
type_ok = validate_all_against_schema(expert_outputs)
unit_ok = validate_units(expert_outputs)
logic_ok = check_logic_consistency(expert_outputs)
if delta_conf > 0.25 or !type_ok or !unit_ok or !logic_ok:
constraint = {
type: detect_conflict_type(),
detail: "Variablen-Typisierung im Code verletzt physikalische
Fließkomma-Präzision: float64 erforderlich, int gefunden. Pattern
CLOSED_LOOP_01 erfordert while mit Konvergenz.",
expected: load_schema("physik_output_v1.json"),
actual: expert_outputs.code.y_i,
delta: delta_conf,
dag_id: dag_id,
failing_module: "code_experte"
}
log_audit(event="fusion_constraint", constraint=constraint,
dag_id=dag_id)
if iteration_count < MAX_ITER=3:
// nur fehlerhaftes Modul neu triggern mit Constraint als
zusätzlichem Input
trigger_rerun(module=constraint.failing_module,
extra_input=constraint, budget_increase=20%)
iteration_count++
return fuse(new_outputs) // rekursiv
else:
// Abbruch nach 3 Iterationen
return {
answer: best_effort_merge(expert_outputs),
flag: "NON_CONVERGENT",
provenance: collect_provenance(expert_outputs),
audit: get_audit_log(dag_id),
constraints_tried: all_constraints
}
else:
return {
answer: merge_with_template(expert_outputs),
flag: "CONVERGENT",
provenance: collect_provenance(expert_outputs),
audit: get_audit_log(dag_id),

12. Selbstoptimierung - RL Loop und Continual Learning
12.1 Logging
Jeder DAG Pfad geloggt: dag_id, Router Votes, Decomposer Output, Blackboard
Patterns, E_i mit c_i, t_i, Fusion Constraints, Iterationen.
Speicherung: JSONL in S3, OpenTelemetry Trace.
12.2 Trigger für Training
Wenn c_i sinkt bei gleicher t_i über 100 Requests -> Drift
Wenn Mikro-Iterationen für Modul C > 2 im Durchschnitt -> Halluzination
Wenn TMR disagreement > 10% -> Router veraltet
Wenn type_check Fail Rate > 2% -> Schema oder Modell veraltet

12.3 Training Ablauf
Damit endet Re-Zertifizierungs Hölle. Update ist lokal, nicht global. LRU Prinzip.
